# Endless Progression — การเปลี่ยนแปลงระบบเกม

เริ่มพัฒนา: 2026-10-27

เอกสารนี้บันทึกกติกาที่ตกลง การทำงานที่ลงมือแล้ว และผลตรวจจริง ตัวเลขเป็นชุดตั้งต้นสำหรับทดลองสมดุล ไม่ใช่ผลรับรองความยากจากผู้เล่นจริง

## จากระบบเดิมสู่ระบบใหม่

| เรื่อง | เดิม | ใหม่ |
|---|---|---|
| ผ่านมังกรด่าน 7 | จบเกมและล้าง checkpoint | เลือกการ์ดแล้วกลับด่าน 1 ของรอบถัดไป |
| ความยาก | คงที่ | เพิ่มตามรอบ พร้อมศัตรู Elite |
| บิลด์ | สเตตัสพื้นฐานตัวละคร | พื้นฐาน + Rebirth + การ์ด + ผลชั่วคราว |
| เมื่อตาย | ลองด่านเดิมได้ | จบการเล่น ล้างการ์ด รับแต้มสะสม |
| ความก้าวหน้าถาวร | ไม่มี | Rebirth แยกตัวละคร การ์ดปลดล็อกส่วนกลาง และสถิติ |
| เซฟ | ตัวละครและด่าน | รวมรอบ บิลด์ ข้อเสนอการ์ด แต้ม สถานะด่าน และความก้าวหน้าถาวร |

## วงจรการเล่น

เลือกตัวละคร → เลือกการ์ดเริ่มต้น → สู้ → ผ่านด่านและเลือกการ์ด → เข้าประตู → ผ่านมังกร → วนรอบที่ยากขึ้น → ตาย/จบการเล่นเอง → รับแต้ม → Rebirth → เริ่มใหม่

- หนึ่งรอบมี 7 ด่าน ใช้ฉาก ศัตรู และสกิลพื้นฐานเดิม
- เลือก 1 จาก 3 ใบตอนเริ่มเล่นและหลังผ่านทุกด่าน ได้ 8 ใบก่อนเริ่มรอบ 2
- เข้าด่านใหม่ HP เต็มและคูลดาวน์พร้อมใช้ การ์ดคงอยู่เมื่อเปลี่ยนด่านและเปลี่ยนรอบ
- เมื่อตายหรือเลือก End Run จะล้างบิลด์ รับแต้มที่ทำได้ และคงโบนัสถาวร
- Save & Main Menu และการปิดเกมเป็นการพัก ไม่ใช่จบการเล่น Continue เริ่มการต่อสู้ด่านปัจจุบันด้วย HP เต็มตามรูปแบบ checkpoint เดิม
- ถ้าบันทึกหลังผ่านด่าน การกลับมาเล่นจะไม่สร้างการต่อสู้นั้นซ้ำ และต้องเลือกข้อเสนอเดิมก่อนเข้าประตู
- เริ่มการเล่นใหม่ขณะมีเซฟต้องยืนยัน จบครั้งเดิมและรับแต้มก่อนแทนที่

|---|---|---|

| tanky | ความจุโล่ +20%, conversion +0.5 จุดเปอร์เซ็นต์ | 3; New |

| duration | ระยะเวลาผลสกิล +20% | 3; ปลดล็อกผ่านด่านแม่มด |

| dragon | ดาเมจทั้งหมด +15% แลก HP สูงสุด −5% | 3; ปลดล็อกผ่านมังกร |

- Evergreen เลือกเพิ่มครั้งที่ n ได้ผลพื้นฐาน / √n ไม่จำกัดจำนวนระดับ
- ผลรวมคำนวณตรงถึงระดับ 4096 แล้วใช้ integral approximation ต่อเนื่องสำหรับระดับสูงมากเพื่อไม่ให้การคำนวณแพงตามจำนวนระดับ
- โบนัสเปอร์เซ็นต์ของสเตตัสเดียวกันบวกสะสม; โบนัสเฉพาะสกิลเป็นอีกชั้นหนึ่ง
- แต่ละข้อเสนอไม่มี ID ซ้ำ มี Evergreen อย่างน้อยหนึ่งใบ และไม่มีการ์ดของตัวละครอื่นหรือใบที่เต็มแล้ว
- ไม่สุ่มการ์ดเพิ่มรัศมีให้ Shadow เพราะสกิลปัจจุบันไม่มีพื้นที่โจมตีที่ได้ประโยชน์จากค่านี้
- หน้าการ์ดแสดงโบนัสที่จะเพิ่มจริงของ Evergreen ในระดับถัดไป และขยายตัวอักษรตามการตั้งค่า
- การ์ดปลดล็อกเข้ากองสุ่มตั้งแต่การเล่นครั้งถัดไป ใช้รายการปลดล็อกที่ถ่ายไว้ตอนเริ่มการเล่น
- ดาเมจพื้นฐาน สกิล Lunar และ Burn ใช้ค่าที่คำนวณใหม่จากต้นฉบับ; ไม่คูณโบนัสซ้ำตอนกระทบหรือแต่ละ tick
- ไม่เพิ่มปุ่มสกิลใหม่ ไม่เพิ่มของแต่งหรือภาพการ์ดเฉพาะใบ

## ความยาก

ให้ L = รอบ − 1

- HP ศัตรู × 1.55^L; ดาเมจ × 1.20^L
- ความเร็วเดินเพิ่ม min(4% × L, 24%)
- คูลดาวน์โจมตีลด min(3% × L, 25%) เวลาบอกท่า wind-up คงเดิม
- Elite = ceil(จำนวนศัตรูทั่วไป × min(10% × L, 35%)) สุ่มตัวด้วย seed ประจำการเล่น/รอบ/ด่าน
- Elite ได้ HP ×1.6 ดาเมจ ×1.2 ความเร็ว ×1.1 ขนาด ×1.1 พร้อมสีและวงแหวนจาก VFX เดิม
- บอสไม่เป็น Elite; ด่านมังกรที่ไม่มีศัตรูทั่วไปจึงไม่มี Elite
- ใช้ bounded arithmetic ที่ขีดจำกัดตัวเลขเพื่อป้องกัน Infinity/NaN ไม่จำกัดรอบที่ระดับกติกา
- รุ่นนี้ไม่เพิ่มแพตเทิร์นบอสหรือศัตรูชนิดใหม่

## แต้มและ Rebirth

| เหตุการณ์ | แต้มรอบแรก |
|---|---:|
| ผ่านด่านทั่วไป | 5 |
| ผ่านด่านแม่มด | 15 |
| ผ่านด่านโกเลม | 20 |
| ผ่านด่านมังกร | 30 |
| โบนัสครบหนึ่งรอบ | 40 |
| รวมรอบแรก | 125 |

- รางวัลแต่ละรายการ × (1 + 0.5L) แล้วปัดลง ผลรวมสามรอบแรกคือ 125 + 185 + 250 = 560 แต้ม
- รางวัลมาจากผ่านด่านเท่านั้น ไม่ให้จากจำนวน kill หรือการตาย แต่ละด่านจ่ายครั้งเดียวต่อรอบ
- แต้มระหว่างเล่นยังไม่ใช่เงินในกระเป๋า จะรับเมื่อจบการเล่น
- แต้ม โบนัส และจำนวน Rebirth แยกตัวละคร การ์ดปลดล็อกใช้ร่วมกัน
- ราคา = 30 + 10r + 2r² โดย r เป็นจำนวน Rebirth ที่ทำแล้ว: 30, 42, 58, 78, ...
- เลือก HP, ดาเมจ หรือเกราะทั้งสองชนิดหนึ่งด้านต่อการซื้อ
- อัปด้านเดิมครั้งที่ n: HP +3%/√n, ดาเมจ +2%/√n หรือเกราะ +2/√n
- ไม่ล้างโบนัสเดิมหรือแต้มคงเหลือ ไม่จำกัดจำนวนครั้ง และไม่ซื้อให้ตัวละครที่มีการเล่นค้างอยู่
- หน้าจอแสดงราคา ผลเพิ่มครั้งถัดไป โบนัสปัจจุบัน และสถิติรอบ/ด่านสูงสุดที่ผ่าน

## โครงสร้างและการบันทึก

- `CardDefinition` / `ProgressionConfig`: ScriptableObject สำหรับปรับข้อมูลการ์ด ความยาก รางวัล และ Rebirth
- `Progression`: กติกาการเล่น ข้อเสนอ รางวัล กระเป๋า และการซื้อ Rebirth
- `PlayerProgression`: คำนวณ config ส่วนตัวจากต้นฉบับทุกครั้ง ไม่เขียนกลับ asset ตัวละคร และทำลายสำเนาเมื่อจบ scene
- `LevelManager` / `EnemyController`: การวนรอบ สถานะหลังตาย และการปรับศัตรูครั้งเดียวต่อ scene
- `GameUIProgression`: หน้าการ์ด Rebirth บิลด์ และข้อความความก้าวหน้า ใช้ safe area และ screen stack เดิม
- `ProgressionSetup`: เมนู Tools > Magic Game > Set Up Endless Progression สร้าง config/การ์ดและเพิ่มเฉพาะส่วน UI ใน prefab เดิม โดยไม่เขียนฉากใหม่และคงค่าที่ปรับไว้เมื่อเรียกซ้ำ

ใช้ PlayerPrefs key `MagicGame.Progression.v1` เก็บ JSON version 1 ชุดเดียว ประกอบด้วยข้อมูลถาวร การเล่นปัจจุบัน และผลล่าสุด การรับแต้มกับการลบการเล่นเกิดใน write เดียวกันเพื่อป้องกันรับซ้ำ

มี `hasRun` ระบุว่ามีการเล่นค้างอยู่จริง เนื่องจาก Unity JsonUtility อาจแปลงคลาสที่เป็น null กลับมาเป็นอ็อบเจ็กต์ว่างเมื่ออ่านเซฟ หากไม่มี flag นี้ การโหลดหลังตายหรือซื้อ Rebirth อาจถูกปฏิเสธทั้งชุด

สถานะการเล่น: Starter → Fighting → Reward → Cleared → Fighting ของด่านถัดไป ข้อเสนอการ์ดทั้งสามใบถูกบันทึกก่อนแสดง โหลดแล้วจึงไม่สุ่มใหม่

เซฟเดิม `MagicGame.Checkpoint.v1` ย้ายตัวละครและด่านเข้ารอบ 1 ให้การ์ดเริ่มต้นหนึ่งครั้ง โดยไม่แจกแต้มย้อนหลัง เซฟผิดรูปแบบหรือ version ไม่รองรับถูกปฏิเสธ

## สถานะงานและการตรวจ

### ทำแล้ว

- เพิ่มระบบข้อมูลและเซฟ การ์ด 18 ใบ Rebirth แยกตัวละคร การ์ดปลดล็อก และสถิติ
- เชื่อมโบนัสเข้ากับตัวละครและสกิลโดยใช้ config สำเนา
- เชื่อมการวนรอบ รางวัลหลังผ่านด่าน การจบหลังตาย และ Elite
- เพิ่มหน้าการ์ด Rebirth และบิลด์ใน UI เดิม พร้อมปุ่ม End Run
- เพิ่ม Edit Mode tests สำหรับหลายรอบ การเซฟ รางวัลซ้ำ Rebirth และ migration; ปรับ gameplay/UI tests ให้ตรงกติกาใหม่

### ผลตรวจจริง

- คอมไพล์ Unity 6000.6.3f1 ผ่านหลังการปรับระบบและหน้าจอ
- สร้าง card/config assets และเพิ่มหน้าจอใน prefab ผ่าน Unity Editor แล้ว
- **Edit Mode 47/47 ผ่าน** รวมหลายรอบ การคิดแต้ม การรับรางวัลครั้งเดียว การโหลดข้อเสนอเดิม ราคากับโบนัส Rebirth การแยกตัวละคร การ์ดที่ใช้ได้ และการย้ายเซฟเก่า
- **Play Mode 44/44 ผ่าน** รวมการต่อสู้เดิม การเดินเข้าประตูจริง มังกรบิน การวนรอบทั้งห้าตัวละคร การโหลดด่านที่เคลียร์แล้ว การล้างโบนัสหลังตาย การรักษา asset ต้นฉบับ ข้อความขนาดใหญ่ และการซื้อ Rebirth ผ่านปุ่มจริง
- การทดสอบ scene จริงพาตัวละครทั้งห้าผ่านครบสามรอบ รวม 105 ด่าน และตรวจบิลด์ 22 ระดับกับแต้มรวม 560 ต่อการเล่น การทดสอบนี้กำจัดศัตรูด้วยโค้ดเพื่อยืนยันการเปลี่ยนฉากและรางวัล ไม่ใช่การรับรองว่าสู้ผ่านสามรอบด้วยความยากจริง
- ตรวจหน้าการ์ดและ Rebirth ใน Game View 1280×720 และ 1600×720 พร้อมตัวอักษร 150% และ safe area จำลอง แก้ข้อความหัวข้อที่ถูกตัด เพิ่ม autosizing และเพิ่มการทดสอบข้อความ/ปุ่ม Rebirth
- ตัวตรวจ asset/GUID ตรวจ 565 ไฟล์ พบ **0 errors และ 0 warnings**; source whitespace check ผ่าน
- Unity Console หลังการทดสอบสุดท้าย: **0 errors และ 0 warnings**
- ฉาก งานภาพตัวละคร ลำดับ build scenes และ package dependencies ไม่เปลี่ยน มีการเปลี่ยน generated UI prefab และเพิ่ม card/config data assets พร้อมไฟล์ .meta
- ภาพและรายงานอยู่ใต้ Logs ซึ่งไม่รวมในการ commit: `EndlessProgression-EditMode.json`, `EndlessProgression-PlayMode.json`, `EndlessProgression-Cards-16x9.png`, `EndlessProgression-Cards-Wide.png`, `EndlessProgression-Rebirth-Wide.png`
- ข้อมูลเซฟ การตั้งค่าข้อความ และ Game View ที่ใช้ตรวจภาพถูกสำรองและคืนค่าหลังตรวจ ชุดทดสอบสำรอง/คืนข้อมูลเอง และตั้งค่า routing ของคีย์บอร์ดเฉพาะระหว่างทดสอบเพื่อให้รันได้แม้ Editor ไม่ได้โฟกัส

### ขอบเขตการยืนยันสมดุล

การทดสอบอัตโนมัติยืนยันกติกาและความถูกต้องของระบบ แต่ไม่ทดแทนผู้เล่นจริงในการตัดสินความยาก ความสนุก และความคุ้มค่าของการ์ด/รางวัล
